# DBBEMN

Distributed Blood Bank & Emergency Matching Network. The project follows the phases and locked technology rules in [`SPEC.md`](./SPEC.md): plain JavaScript, PostgreSQL, and parameterized SQL through `pg`, with no ORM.

## Current scope

Phase 1 provides the real database migrations, per-city schemas and triggers, a repeatable small development seed, invariant verification, and real-database tests for compatibility and unit-state transitions. The API and portals are not part of this phase yet.

## Database commands

The Replit-managed PostgreSQL database supplies `DATABASE_URL`; do not add it as a manually managed secret.

```sh
pnpm run migrate
pnpm run seed:small
pnpm run verify:phase1
pnpm run test:phase1
pnpm run verify:invariants
```

For isolated test schemas, set the prefix consistently on every command:

```sh
SCHEMA_PREFIX=t_ pnpm run migrate
SCHEMA_PREFIX=t_ pnpm run seed:small
SCHEMA_PREFIX=t_ pnpm run verify:phase1
SCHEMA_PREFIX=t_ pnpm run test:phase1
SCHEMA_PREFIX=t_ pnpm run verify:invariants
```

The seed contains fictional development donor identities and no patient records. It is idempotent and safe to rerun.

## Layout

- `db/migrations/catalog/` — shared types, compatibility function, and catalog tables.
- `db/migrations/shard/` — per-city hot/history/read schema template.
- `backend/src/db/shard-router.js` — city allow-list and safe schema-name construction.
- `scripts/` — migration, seed, schema-listing, and invariant commands.
- `backend/tests/phase1.test.js` — Node test-runner tests against PostgreSQL.
- `docs/DESIGN.md` — database rationale, assumptions, and the production mapping of simulated parts.

Every value in SQL statements is bound as a parameter. The only interpolated SQL identifiers are generated by `schemasFor` from the fixed city allow-list and validated prefix.
